## 3. 为什么是两套论文

两套是**彼此独立**的解题产线，不是同一篇的两个版本：

- **01（A 项目）**：长报告式论文，47 页，113 个占位符全部由台账渲染，11 条 claim；方法学上把“数据核实”作为建模前置，交付四套 0–6 分级口径。
- **02（beer 项目）**：竞赛投稿式论文，12 页；重新做了一遍数据取证（`analysis/`），用更严格的台账/复现协议（配置冻结、validation plan 先于 candidate、holdout 曝光预算），但最终仍因 `contest.yaml` 在 init 后修改导致的 sha 冲突而无法 `final=true`。

两套的局限与未完成项都在各自包的 `docs/` 中逐条列出，未作修饰。

## 4. 复现

各包是自包含的：`paper/`（md/tex/pdf + 构建脚本）、`src/`（建模代码）、`data/`（清洗后数据 + 划分 + 原始附件）、
`experiments/`（实验元数据）、`figures/`、`ledger.json`（台账）、`contest.yaml`（协议配置）。

- 项目 1：见 `packages/01-A-mathorcup-2026-a/REPRODUCE.md`
- 项目 2：见 `packages/02-beer-2026-a/docs/DELIVERY-NOTES.md` 第 5 节「复现入口」
- 依赖：Python 3.12 + numpy / pandas / scipy / scikit-learn / matplotlib / openpyxl；论文另需 pandoc + XeLaTeX（ctexart）

> 原机器的绝对路径（`/Users/...`）仍出现在部分复现文档中，请按本仓库布局替换为相对路径。
